# Header Grup Sidebar Lebih Kontras, Ikon Grup saat Collapsed, dan Submenu Flyout Bertingkat

## Problem Statement

Judul grup (`section-label`) di sidebar memakai warna teks `rgba(255, 255, 255, .4)` (`resources/css/app.css:51`) — sangat dekat dengan warna background gradient biru sidebar (`var(--color-brand-light)`/`var(--color-brand-dark)`, `app.css:21`), jauh lebih redup dibanding warna item menu biasa (`rgba(255, 255, 255, .9)`, `app.css:43`). Akibatnya judul 9 grup (`config/marketama.php`) sulit dibaca sekilas, padahal itu satu-satunya penanda pengelompokan di antara 119 menu.

Saat sidebar dipersempit jadi mode icon-only (`body.sidebar-collapsed .sidebar:not(:hover)`), aturan `app.css:64-67` menyembunyikan seluruh `.section-label` (`display: none`) — termasuk `.section-label-icon` yang sudah dirender di markup (Blade `sidebar.blade.php:25`, Vue `Sidebar.vue:225`). Jadi walau tiap grup sudah punya ikonnya sendiri di data (`config/marketama.php`), user yang mempersempit sidebar kehilangan seluruh pemisah visual antar grup — hanya tersisa daftar ikon menu individual tanpa pengelompokan.

Submenu (item dengan `children`) saat ini expand inline di bawah parent-nya (accordion — `toggleSubmenu` di `Sidebar.vue:122-125`, script generik `[data-collapse-toggle]` di `layouts/app.blade.php:38-46`), mendorong turun item-item lain di bawahnya dan menambah tinggi total sidebar. Backlog 009 malah secara eksplisit meng-out-of-scope-kan pola flyout saat itu ("Flyout/popover submenu saat hover ikon dalam mode collapsed-icon-only"). Dengan banyak grup berisi `children`, accordion ini membuat sidebar bisa jadi sangat panjang kalau beberapa submenu dibuka bersamaan, dan modelnya tidak scalable untuk submenu di dalam submenu (saat ini `config/marketama.php` baru 2 level: `items` → `children`, belum ada `children` di dalam `children`).

## Solution

1. **Kontras judul grup:** naikkan opacity/warna teks `.section-label` (dan `.section-label-icon` yang warnanya ikut) dari `rgba(255, 255, 255, .4)` ke level yang jelas lebih terang (mendekati warna item menu biasa, tapi tetap dibedakan dari `.nav-link` aktif supaya hierarki "judul grup" vs "menu" masih terasa) — perubahan CSS murni di `app.css:51-53`, dipakai bersama oleh kedua stack (Blade & Vue) karena satu file CSS yang sama.
2. **Ikon grup tetap tampil saat collapsed:** ubah aturan collapsed-icon-only (`app.css:64-67`) supaya hanya `.section-label-text` dan `.nav-chevron` yang disembunyikan di mode icon-only — `.section-label-icon` tetap dirender sebagai separator ikon antar grup, sejajar visual dengan `.nav-link-icon` milik menu-menu di bawahnya (yang sudah tetap tampil di mode itu). Tooltip (`title`) pada `.section-label` memastikan nama grup tetap bisa dibaca saat hover ikon dalam mode sempit.
3. **Submenu jadi flyout bertingkat:** ubah interaksi item ber-`children` dari accordion inline menjadi panel flyout yang muncul di sebelah **kanan** item parent saat mouseover atau klik — bukan mendorong isi sidebar ke bawah. Kalau salah satu child di flyout itu sendiri punya `children` (struktur data berlapis lebih dari 2 level — mekanisme dibuat generik/rekursif agar siap menampung ini meskipun `config/marketama.php` saat ini baru 2 level), flyout levelnya ditampilkan lagi di sebelah **kanan** flyout sebelumnya (cascading ke kanan), bukan menumpuk ke bawah.

## User Stories

1. Sebagai pengguna admin yang melihat sidebar dalam mode lebar penuh, saya ingin judul grup (misal "MASTER DATA", "MONITORING HARIAN") terbaca jelas sekilas tanpa harus menyipitkan mata, supaya saya cepat orientasi grup mana yang sedang saya lihat.
2. Sebagai pengguna admin yang mempersempit sidebar jadi mode ikon-saja, saya ingin tetap melihat ikon pemisah tiap grup di antara ikon-ikon menu, supaya saya tidak kehilangan pengelompokan visual walau judul teksnya disembunyikan.
3. Sebagai pengguna admin dalam mode ikon-saja, saya ingin hover ikon grup menampilkan nama grup lewat tooltip, supaya saya tetap tahu nama grup itu tanpa perlu melebarkan sidebar.
4. Sebagai pengguna admin yang mengarahkan mouse ke menu yang punya submenu, saya ingin submenu itu muncul melayang di sebelah kanan tanpa mendorong menu lain di bawahnya, supaya posisi sidebar tetap stabil dan saya tidak perlu scroll tambahan setelah submenu terbuka.
5. Sebagai pengguna admin yang mengklik (bukan hover, misal via keyboard/touch) menu berSubmenu, saya ingin submenu tetap bisa dibuka lewat klik/Enter, supaya interaksi tidak tergantung mouse hover saja.
6. Sebagai pengguna admin yang submenu-nya sendiri punya submenu lagi (struktur berlapis), saya ingin submenu level berikutnya muncul di kanan submenu sebelumnya (bukan di bawahnya), supaya pola "flyout ke kanan" konsisten di semua level.
7. Sebagai pengguna admin yang sedang berada di sebuah menu (child aktif), saya ingin tahu menu itu ada di grup/submenu mana walau flyout-nya sedang tertutup, supaya saya tidak kehilangan orientasi lokasi saat ini di sidebar.
8. Sebagai pengguna admin yang flyout submenu-nya sedang terbuka, saya ingin flyout tertutup saat saya klik di luar area sidebar/flyout, pindah fokus ke item lain, atau menekan Escape, supaya flyout tidak terus menutupi konten halaman.
9. Sebagai pengguna admin yang mengakses lewat layar sempit (mobile, ≤991px), saya ingin submenu tetap bisa dibuka dengan cara yang nyaman untuk layar sempit itu (bukan dipaksa flyout ke kanan yang makan tempat), supaya navigasi di mobile tidak rusak oleh perubahan ini.

## Implementation Decisions

- Perubahan warna (#1) dan visibilitas ikon grup (#2) murni di `resources/css/app.css` (baris 51-53 dan 64-67) — tidak perlu perubahan markup Blade/Vue karena `.section-label-icon` sudah ada di kedua stack; cukup selector CSS yang dikecualikan dari aturan `display: none` mode collapsed.
- Flyout submenu (#3) mengganti mekanisme `toggleSubmenu`/`data-collapse-toggle` **khusus untuk level `item.children` ke bawah** — collapse per grup (`section-label`) dan toggle collapse-all tetap memakai mekanisme accordion yang sudah ada (tidak disentuh), karena flyout hanya relevan untuk level submenu-menu, bukan grup-grup.
- Markup: tiap `<li>` yang punya `children` diberi `position: relative`; panel flyout-nya (`<ul>` turunan) diberi class baru (misal `.nav-flyout`) dengan `position: absolute; left: 100%; top: 0;` relatif terhadap `<li>` itu, `min-width` secukupnya (tidak ikut lebar sidebar), `z-index` lebih tinggi dari dropdown pencarian yang sudah ada (`.sidebar-search-results` pakai `z-index: 40`, flyout butuh lebih tinggi karena harus mengambang di atas `main` konten, bukan hanya di atas sidebar) dan `background`/`box-shadow` reuse token yang sama dengan `.sidebar-search-results` (`#002a5c`, `box-shadow 0 4px 12px rgba(0,0,0,.25)`) supaya konsisten secara visual dengan "panel mengambang" yang sudah ada di sidebar.
- Trigger buka: `mouseenter` pada `<li>` (dengan sedikit delay sebelum `mouseleave` menutup, supaya pointer sempat pindah dari parent ke flyout tanpa flyout keburu hilang) **dan** klik/Enter/Space pada link parent (untuk keyboard/touch tanpa hover) — pola delay hover ini baru, tidak reuse kode toggle lain, karena toggle lain (grup, toggle-all) tidak bersifat hover-triggered.
- Submenu berlapis (anak dari anak): ditulis generik/rekursif di kedua stack (Blade: komponen partial `sidebar-nav-items` yang sudah ada di `resources/views/components/ui/organisms/partials/sidebar-nav-items.blade.php` dipanggil ulang untuk level berikutnya; Vue: ekstrak bagian render item jadi sub-komponen rekursif, mis. `SidebarNavItem.vue`, dipanggil dari dirinya sendiri untuk `item.children`) — supaya `left: 100%` pada tiap level flyout otomatis menumpuk ke kanan tanpa hardcode offset per level. `config/marketama.php` sendiri tidak diubah (masih 2 level) — ini murni menyiapkan mekanisme render agar generik.
- Hanya satu flyout per level dibuka pada satu waktu (membuka flyout sibling lain menutup flyout yang sedang terbuka di level yang sama) — state "flyout mana yang terbuka" per level disimpan di memori (bukan `localStorage`, beda dari state collapse grup/sidebar yang memang harus persist) karena flyout bersifat sementara/kontekstual seperti dropdown pencarian yang sudah ada.
- Indikator lokasi aktif tanpa membuka flyout (story #7): parent item yang salah satu `children`-nya adalah `currentSlug` tetap diberi class `active`-style (border/background redup) pada link parent-nya sendiri, memakai pola yang sama dengan `.nav-link.active` yang sudah ada (`app.css:45`) — bukan komponen baru.
- Penutupan flyout (story #8): klik di luar `<li>`+panel flyout (listener `document` `click`, cek `event.target.closest(...)`, sama seperti pola `sidebar-search` yang sudah ada di `sidebar.blade.php:217-219`/`Sidebar.vue` blur), `Escape`, atau mouse keluar (dengan delay) — konsisten dengan pola dropdown pencarian yang sudah diimplementasi di ticket 012.
- Breakpoint mobile (story #9, ≤991px): flyout **tidak** diaktifkan di breakpoint itu — kembalikan ke accordion inline lama (`toggleSubmenu` existing) untuk lebar ≤991px, karena flyout ke kanan tidak praktis di layar sempit dan tidak ada ruang untuk mengambang. Deteksi lewat media query CSS yang mengatur `.nav-flyout` jadi `position: static` (otomatis jadi "inline di bawah" seperti sekarang) di bawah breakpoint itu, bukan deteksi lebar lewat JS.

## Testing Decisions

- Test Feature Laravel yang mem-assert markup Blade memuat class `.section-label` dengan `.section-label-icon` di dalamnya (parity dengan existing test markup sidebar, lihat pola `MenuTest`/sidebar test kalau ada), dan memuat elemen flyout baru (`data-flyout-toggle`/`data-flyout-panel` atau nama atribut yang disepakati saat implementasi) pada item yang punya `children`.
- Verifikasi manual (didokumentasikan di PR, konsisten dengan keputusan testing 009/012 untuk interaksi Vue tanpa test runner JS komponen): kontras warna judul grup di mode lebar penuh; ikon grup tetap tampil & tooltip jalan di mode icon-only; hover item berSubmenu menampilkan flyout di kanan tanpa mendorong layout; klik/Enter juga membuka flyout; flyout tertutup saat klik di luar/Escape/mouse keluar; di viewport ≤991px submenu kembali ke accordion inline (bukan flyout) — verifikasi berlaku di kedua stack (Blade & Vue/Inertia).

## Out of Scope

- Menambah level nesting baru ke `config/marketama.php` (`children` di dalam `children`) — ticket ini hanya menyiapkan mekanisme render yang generik/rekursif, tidak menambah data menu 3 level yang sesungguhnya.
- Animasi/transisi flyout muncul-hilang (fade/slide) — cukup show/hide instan lewat CSS `display`, transisi halus bisa jadi perbaikan terpisah (konsisten dengan keputusan out-of-scope animasi di 009).
- Roving focus penuh dengan arrow key antar item di dalam flyout (navigasi keyboard mendalam) — cukup Tab/Enter/Escape standar, seperti batas yang sama dipakai di pencarian menu (012).
- Mendesain ulang ikon grup (`section-label-icon`) itu sendiri — ticket ini hanya mengubah kontras warna dan visibilitasnya saat collapsed, bukan mengganti ikon (sudah pakai Lucide sejak 013).
- Mengubah mekanisme collapse per grup (`section-label` grup) atau collapse-all yang sudah ada (009/010) — flyout hanya mengganti cara level `item.children` ditampilkan, bukan level grup.
