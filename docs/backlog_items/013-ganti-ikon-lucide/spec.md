# Ganti Sistem Ikon dari Font Awesome ke Lucide

## Problem Statement

Semua ikon di aplikasi ini (sidebar, topbar, tombol-tombol aksi) memakai Font Awesome 5 Free solid (`fas fa-*`), di-self-host di `public/vendor/fontawesome/` (`docs/TECH.md:45`, `docs/STYLE_GUIDE.md:10`). User merasa style ikon solid/filled ini kurang cocok untuk tampilan admin yang diinginkan, dan ingin beralih ke style outline yang lebih modern dan konsisten — Lucide dipilih karena cakupan ikonnya luas, penting karena sidebar punya 119 menu + beberapa grup yang masing-masing butuh satu ikon representatif, dan dengan cakupan yang luas kemungkinan menemukan ikon yang pas untuk tiap menu (tanpa harus memaksakan ikon yang kurang representatif karena tidak ada alternatif) jadi lebih besar dibanding library dengan set ikon yang lebih kecil (misal Heroicons).

Font Awesome adalah webfont (ikon dirender lewat CSS class pada elemen `<i>`, mengandalkan file font + stylesheet). Lucide tidak punya distribusi webfont resmi — ikonnya didistribusikan sebagai file SVG per-ikon. Jadi migrasi ini bukan sekadar ganti nama class, tapi ganti mekanisme rendering ikon itu sendiri, di kedua stack (Blade & Vue/Inertia) sekaligus.

## Solution

Ganti seluruh titik pemakaian Font Awesome di aplikasi dengan Lucide, di-self-host sebagai file SVG individual di `public/vendor/lucide/` (disalin manual, bukan lewat npm — konsisten dengan pola `public/vendor/fontawesome/` yang sudah ada, dan dengan histori project yang menghindari instalasi npm untuk aset vendor semacam ini). Icon atom di kedua stack (`icon.blade.php` / `Icon.vue`) dirombak agar menerima `name` berupa nama ikon Lucide (misal `home`, `clock`) dan merender SVG tersebut inline, bukan `<i class="fas fa-{name}">`.

Ada tiga titik pemakaian ikon yang perlu dibedakan penanganannya:

1. **Icon atom (`x-ui.atoms.icon` / `<Icon>`)** — dipakai di beberapa tempat secara eksplisit lewat komponen. Ganti implementasi internalnya untuk resolve nama Lucide ke file SVG dan echo isinya inline, tetap menerima `$attributes`/atribut tambahan (class, dll.) yang diteruskan ke elemen SVG root.
2. **Icon menu di sidebar (`config/marketama.php`)** — field `'icon'` di 119+ entri menu (dan beberapa grup) saat ini menyimpan FULL class string (`'fas fa-home'`), dirender langsung sebagai `<i class="{{ $item['icon'] }}">` (Blade: `resources/views/components/ui/organisms/partials/sidebar-nav-items.blade.php`) / `<i :class="item.icon">` (Vue: `resources/js/Components/ui/organisms/Sidebar.vue`). Field ini diganti menjadi nama ikon Lucide polos (misal `'home'`, bukan `'fas fa-home'`), dan kedua partial sidebar diganti untuk merender lewat Icon atom yang baru (`<x-ui.atoms.icon :name="$item['icon']" />` / `<Icon :name="item.icon" />`) bukan `<i class="...">` mentah lagi — ini juga menyelaraskan sidebar dengan aturan "Komponen UI wajib dipakai" di `CLAUDE.md` root, yang sebelumnya tidak dipatuhi di titik ini.
3. **Pemakaian `<i class="fas fa-*">` mentah di luar config menu** — ditemukan di `resources/views/components/ui/organisms/topbar.blade.php`, `resources/js/Components/ui/organisms/Topbar.vue`, `resources/views/components/ui/molecules/password-input.blade.php`, `resources/views/area/design.blade.php` (termasuk string HTML yang dibangun di JS inline untuk popup/tombol dinamis), `resources/views/tracking/history.blade.php` (termasuk string HTML di JS inline untuk kontrol peta), dan `fa-chevron-down` untuk `nav-chevron` di `resources/views/components/ui/organisms/partials/sidebar-nav-items.blade.php`. Semua titik ini diganti memanggil Icon atom (untuk markup Blade/Vue statis) atau, untuk string HTML yang dibangun di JS inline (template literal di `area/design.blade.php` dan `tracking/history.blade.php`), ditulis ulang supaya menyisipkan markup SVG Lucide yang sepadan secara langsung di template literal tersebut (karena titik itu bukan konteks Blade/Vue component, jadi tidak bisa memanggil Icon atom).

Pemetaan nama ikon FA → Lucide dilakukan satu per satu per kebutuhan semantik ikonnya (bukan pencarian nama yang mirip), misal `fa-home` → `home`, `fa-chevron-down` → `chevron-down`, `fa-user-times` → `user-x`, `fa-draw-polygon` → `shapes` atau ikon Lucide yang paling representatif untuk "polygon area". Mapping lengkap 119+ entri ditulis sebagai bagian dari implementasi (di PR), bukan di spec ini — spec ini menetapkan mekanisme migrasinya, bukan daftar mapping itu sendiri.

## User Stories

1. Sebagai pengguna admin, saya ingin seluruh ikon di sidebar tampil dalam style outline Lucide yang konsisten, supaya tampilan aplikasi lebih modern dan seragam, bukan campuran Font Awesome solid lama.
2. Sebagai pengguna admin yang membuka salah satu dari 119 menu, saya ingin ikon menu tersebut tetap representatif terhadap fungsinya (misal ikon rumah untuk Dashboard, ikon motor untuk menu terkait motoris), bukan ikon generik yang tidak ada hubungannya, walaupun library ikonnya berganti.
3. Sebagai pengguna admin yang melihat tombol-tombol aksi di topbar (loading barang, barang canvassing, design area, notifikasi, user menu), saya ingin ikon-ikon tersebut juga ikut berganti ke Lucide, supaya tidak ada bagian UI yang "ketinggalan" memakai Font Awesome sementara bagian lain sudah Lucide.
4. Sebagai pengguna admin yang membuka halaman Design Polygon Area atau Tracking Koordinator (yang punya tombol/kontrol dibangun lewat JS inline, bukan markup Blade statis), saya ingin ikon pada kontrol tersebut (search, undo, trash, satelit, map, dll.) juga konsisten Lucide, bukan Font Awesome yang tersisa.
5. Sebagai developer yang menambah menu baru di `config/marketama.php` di masa depan, saya ingin field `'icon'` cukup diisi nama ikon Lucide polos (misal `'home'`), konsisten dengan cara Icon atom menerima `name`, supaya tidak perlu menghafal dua pola berbeda (`'fas fa-x'` penuh vs nama polos).
6. Sebagai developer yang membaca kode sidebar, saya ingin partial sidebar memanggil Icon atom (bukan `<i class="...">` mentah) untuk menampilkan ikon menu, supaya konsisten dengan aturan komponen UI wajib dipakai di `CLAUDE.md` dan mudah diubah mekanismenya lagi di masa depan kalau perlu.

## Implementation Decisions

- **Aset Lucide**: unduh SVG ikon-ikon Lucide yang dibutuhkan (hasil dari mapping 119+ nama ikon + ikon-ikon di topbar/area/tracking/password-input/nav-chevron) dan simpan sebagai file individual di `public/vendor/lucide/<name>.svg`, mengikuti pola self-hosted `public/vendor/fontawesome/` — bukan lewat paket npm (`lucide`, `lucide-vue-next`, dst.), konsisten dengan histori project.
- **Icon atom (Blade)** — `resources/views/components/ui/atoms/icon.blade.php`: baca file `public/vendor/lucide/{name}.svg` (misal lewat `file_get_contents(public_path("vendor/lucide/{$name}.svg"))`) dan echo isinya sebagai HTML mentah, dengan atribut tambahan (`class`, dll.) di-merge ke elemen `<svg>` root lewat `$attributes->merge()` (pola yang sama seperti komponen Blade lain di `CLAUDE.md`).
- **Icon atom (Vue)** — `resources/js/Components/ui/atoms/Icon.vue`: karena file SVG itu aset statis (bukan komponen Vue), import isi SVG sebagai string mentah (Vite punya import suffix `?raw` untuk ini) lalu render lewat `v-html`, atau pendekatan setara yang tidak butuh paket npm icon — tetap menerima atribut fallthrough standar Vue ke elemen root.
- **`config/marketama.php`**: field `'icon'` di seluruh entri menu dan grup diubah dari `'fas fa-xxx'` menjadi nama ikon Lucide polos (`'xxx'`), lewat mapping manual 1:1 berdasarkan makna semantik tiap menu.
- **Partial sidebar**: `resources/views/components/ui/organisms/partials/sidebar-nav-items.blade.php` ganti `<i class="{{ $item['icon'] }}"></i>` jadi `<x-ui.atoms.icon :name="$item['icon']" class="nav-link-icon-svg" />` (atau setara, menyesuaikan class CSS yang sudah ada untuk ukuran/warna ikon di `.nav-link-icon`); `resources/js/Components/ui/organisms/Sidebar.vue` ganti `<i :class="item.icon">` jadi `<Icon :name="item.icon" />` dengan pola yang sama. `fa-chevron-down` untuk `.nav-chevron` di file Blade yang sama ikut diganti lewat Icon atom (`chevron-down`).
- **Topbar**: `resources/views/components/ui/organisms/topbar.blade.php` dan `resources/js/Components/ui/organisms/Topbar.vue` — setiap `<i class="fas fa-*">` statis diganti pemanggilan Icon atom/`<Icon>` dengan nama Lucide yang sepadan (`truck-loading`→`truck`, `boxes`→`package`, `draw-polygon`→ikon representatif polygon, `bell`→`bell`, `bell-slash`→`bell-off`, `user-circle`→`circle-user` atau `user`, dst. — nama final ditentukan saat implementasi).
- **`password-input.blade.php`**: `<i class="fas fa-eye">` diganti Icon atom; toggle JS yang sekarang mengganti `className` elemen `<i>` (`tombol.querySelector('i').className = ...`) diganti logic yang sepadan untuk icon SVG (misal toggle `data-name`/re-render Icon, atau simpan dua elemen SVG `eye`/`eye-off` dan toggle `hidden` di antaranya — pendekatan paling sederhana yang konsisten dengan markup Blade component ditentukan saat implementasi).
- **`area/design.blade.php` & `tracking/history.blade.php`**: ikon statis di markup Blade diganti Icon atom. Ikon yang muncul di string HTML yang dibangun lewat JS inline (template literal untuk popup Leaflet, tombol layer peta, tombol hapus area, dst.) diganti dengan markup `<svg>` Lucide yang disisipkan langsung di template literal tersebut (bukan memanggil Icon atom, karena itu bukan konteks render Blade/Vue) — SVG inline untuk kasus ini bisa ditulis manual sebagai string JS atau di-generate dari file di `public/vendor/lucide/` lewat fetch sekali di awal dan disimpan di variabel JS, pendekatan konkretnya ditentukan saat implementasi.
- **Font Awesome tidak langsung dihapus** dari `public/vendor/fontawesome/` dan `<link>` di `resources/views/app.blade.php` / `layouts/app.blade.php` / `layouts/auth.blade.php` sampai dipastikan tidak ada lagi pemakaian `fas fa-*` di seluruh codebase (grep bersih) — baru setelah itu link stylesheet & folder vendor Font Awesome dihapus sebagai langkah pembersihan akhir.
- **`docs/STYLE_GUIDE.md` dan `docs/TECH.md`** diperbarui untuk menyebut Lucide (self-hosted di `public/vendor/lucide/`) sebagai sistem ikon, mengganti referensi ke Font Awesome.

## Testing Decisions

- Feature test Laravel baru (atau tambahan ke test sidebar yang sudah ada seperti `tests/Feature/SidebarCollapseGrupTest.php`, memakai pola `Blade::render('<x-ui.organisms.sidebar />')`) yang mem-assert: markup sidebar tidak lagi mengandung `fas fa-` sama sekali, dan setiap entri menu/grup dari `config('marketama.menu')` menghasilkan elemen `<svg>` (lewat Icon atom) untuk ikonnya.
- Test tambahan yang mem-assert Icon atom (`<x-ui.atoms.icon name="home" />`) merender tag `<svg>` (bukan `<i class="fas fa-home">`), menggantikan asumsi lama pada pola `fas fa-{name}`.
- Verifikasi manual (didokumentasikan di PR, konsisten dengan keputusan testing 009/010/011 untuk bagian yang tidak punya test runner JS khusus komponen Vue): buka sidebar, topbar, halaman Design Polygon Area, dan halaman Tracking Koordinator — pastikan semua ikon tampil sebagai Lucide outline, tidak ada ikon Font Awesome solid yang tersisa (termasuk ikon yang muncul lewat JS inline seperti popup peta dan toggle password visibility).
- Setelah seluruh migrasi selesai, grep `fas fa-` di seluruh `resources/` dan `config/` harus kosong — dicatat sebagai langkah verifikasi akhir, bisa diotomasi sebagai bagian dari test (assert `grep` kosong) atau cukup dicek manual sekali sebelum PR final.

## Out of Scope

- Mengubah warna, ukuran, atau posisi ikon secara visual di luar yang dibutuhkan migrasi SVG itu sendiri (bukan redesign ulang tampilan sidebar/topbar/halaman lain).
- Favicon atau branding di luar ikon sidebar/topbar/halaman-halaman yang disebut di atas (kalau ada ikon lain di luar lingkup ini, tidak termasuk).
- Fitur icon picker UI (admin memilih ikon dari UI) — pemetaan nama ikon tetap manual lewat `config/marketama.php` seperti sekarang.
- Mengganti mekanisme menu/config lain di luar field `'icon'` (struktur `menu`/`pages`/`tables` di `config/marketama.php` tidak berubah).
- Dark mode / varian warna ikon berbeda per tema — di luar lingkup migrasi library ikon ini.

## Further Notes

- Jumlah titik yang perlu diubah lumayan besar (119+ entri config, plus ~7 file view/komponen dengan pemakaian `<i class="fas fa-*">` mentah) — layak dipecah jadi beberapa tiket tracer-bullet terpisah per area (Icon atom dulu sebagai fondasi, lalu sidebar, lalu topbar+komponen lain, lalu pembersihan Font Awesome) daripada satu PR raksasa.
- Tidak menyentuh tabel data personal/import (`trx_*`, dst.) — migrasi ini murni di layer presentasi (views/components/config), tidak ada perubahan skema database.
