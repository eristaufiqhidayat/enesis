Menu/Show.vue tumbuh jadi switch per tabel

Strong in-process
resources/js/Pages/Menu/Show.vue
resources/js/Components/ui/organisms/DataTable.vue

Before — shallow

After — deep

Problem

Interface sudah lebar seperti implementasinya: lima v-if table.name === '...' dan enam ref untuk drawer per tabel.

Solution

Pindahkan keputusan "tabel X pakai drawer Y" ke 'row_detail' => Class di config/marketama.php, dibaca satu <RowDrawer> generik.

Wins

  • Interface menyusut; implementasi menyerap switch
  • Leverage: satu registry, N tabel
  • Locality: tabel baru cuma sentuh config
Tegangan: beberapa drawer (peta depo, riwayat distributor) genuinely one-off — generalisasi untuk 2-3 tabel saja mungkin belum sepadan. Cek laju pertambahan drawer dulu.

Problem

Dua simpan() membangun baris insert yang bentuknya sama persis, dan keduanya memanggil DesignAreaController::diubah() secara statis dari controller tetangga — tanda seam area-row mutation ada di tempat yang salah.

Solution

Satu AreaPembuat::simpanBaru() menangani chunk-insert + AreaMk::sinkronKode; kedua controller hanya menyiapkan unit list domainnya.

Wins

  • Locality: bug insert hanya di satu tempat
  • Hapus panggilan statis antar controller
  • Leverage: satu implementasi, dua pemanggil
Pengecekan "area sudah ada" TIDAK ikut digabung — dedup kelurahan (kode/nama resmi) dan dedup grid (overlap geometris) beda sifat, jangan dipaksa satu abstraksi.

Problem

Tabel aturan [method, uri, aksi, hak, nama] itu config yang wajar, tapi loop yang mengubahnya jadi route ter-gated ditulis ulang di tiga tempat.

Solution

Satu helper/macro RotaMenu::daftarkan() menerima tabel aturan; tiga call site menyusut jadi daftar slug + controller.

Wins

  • 3 kopi yang harus disinkron jadi 1

Prioritas lebih rendah — rute dibaca sekali saat boot, biayanya cuma biaya sinkronisasi, bukan kompleksitas runtime.

Problem

Tiga page punya call-site Leaflet sendiri di luar peta.js; belum dibaca penuh seberapa banyak yang genuinely duplikat vs berbeda (editable vs preview-only).

Solution

Kalau duplikasinya nyata: satu modul map-preview dipakai GenerateKelurahan + AutoGrid; Design.vue tetap sendiri karena editor vertex-nya memang beda interaksi.

Wins

  • Berpotensi locality, belum terverifikasi
Baca penuh ketiga file dulu — interaksi map yang legitimately berbeda (editable vs preview) bisa membuat modul bersama jadi prop-explosion, bukan deepening.

Top recommendation

Mulai dari #2 — Insert area_polygon

Duplikasinya paling jelas lolos deletion test: hapus satu simpan() dan baris insert yang sama harus ditulis ulang di tempat lain. Juga satu-satunya kandidat dengan panggilan statis antar controller yang aktif membocorkan seam sekarang — bukan spekulasi masa depan seperti #4.

Catatan: modul yang sudah dalam

MenuController@show dan SummaryDepoController dibaca juga — keduanya contoh deep module yang sudah benar (sort/filter/search uniform lewat SumberTabel; adapter tipis ke App\Support\Motoris\SummaryDepo). Tidak perlu dideepen — jadi referensi bentuk yang dituju #1 dan #2.
